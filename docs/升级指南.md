# 升级指南

> 面向普通用户：如何把艾泽旅伴升级到新版本，以及升级会动什么、不动什么。

## 升级会保留什么（全部保留）

| 数据 | 位置 | 升级后 |
| --- | --- | --- |
| 游戏账号（含 GM 等级、封禁记录） | `var/mysql`（acore_auth） | ✅ 保留 |
| 角色与进度 | `var/mysql`（acore_characters） | ✅ 保留 |
| 机器人数据（绑定、策略、缓存） | `var/mysql`（acore_playerbots） | ✅ 保留 |
| 世界库中文化与你的修改 | `var/mysql`（acore_world 相关表） | ✅ 保留 |
| 用户配置（三层模型中的用户层） | `var/config` | ✅ 保留 |
| 客户端数据（dbc/maps/...，约 4 GB） | `var/client-data` | ✅ 保留（版本变化时才需重下） |
| 备份档案 | `var/backups` | ✅ 保留 |
| 管理密码、Realm 名称与地址 | `var/state` | ✅ 保留 |

## 升级步骤

1. **建议先备份**：WebUI「备份」页 → 立即备份
2. 下载新版 FPK：GitHub Releases（或 WebUI「版本」页检查更新后点下载）
3. fnOS 应用中心 → 手动安装 → 选择新 FPK → 覆盖安装（应用名与数据目录不变）
4. 打开应用确认：
   - 能用原管理密码登录
   - 「概览」页启动全部，WorldServer 正常就绪
   - 「服务器」页 Realm 名称与地址未丢失
   - 「账号」页账号列表完整

升级过程中 fnOS 会先停止应用、替换运行时（`target/`），再由升级回调按新载荷重新生成运行配置；数据库不会被重新初始化，也不会重复执行破坏性初始化 SQL（结构升级交给 WorldServer 内置更新器，幂等可续）。

## 升级失败怎么办

- 安装中断 / 失败：旧版本可能已被替换，重新安装一次目标版本 FPK 即可；数据都在 `var/`，不受影响
- 新版启动异常：查看「日志」页 `GSWXY Manager` 与 `worldserver` 日志；多数问题（端口占用、配置键改名）会给出明确原因
- 需要回退：**不要直接安装旧版本 FPK**——旧程序可能不认识新数据库结构。正确做法：
  1. 用「备份」页在升级前创建的备份恢复（回滚数据库到升级前）
  2. 恢复完成后再安装旧版 FPK

## 关于降级与回滚

- WebUI 的「恢复备份」会拒绝来自更新程序版本的备份（防止旧程序读不懂新结构）
- 没有无条件一键回滚：降级必须配合数据库备份恢复，这是刻意设计
- 在线更新检查只读不安装；FPK 安装始终由 fnOS 应用中心执行

## 版本号与通道

- 稳定版：纯 `x.y.z`（如 `1.1.0`）
- 测试版：`x.y.z-nightly.N`，功能较新但未经完整回归
- 版本页的「检查更新」默认查稳定版；nightly 需手动切换通道；GitHub API 不通时自动走镜像线路，检查失败会如实提示（不会误报"已是最新"）
- FPK 文件名、应用内显示版本、GitHub Release 版本三者一致；不一致时构建直接失败

## 从 1.0.x 升级到 1.1.0

- 数据完全兼容：账号、角色、机器人、配置、备份与客户端数据全部保留；1.1.0 不会重新初始化数据库
- 安装 1.1.0 后：管理界面全面翻新（各页功能只增未减）、桌面名称变为「艾泽旅伴」、图标更换；应用数据目录与应用身份不变
- 建议升级前在旧版「备份」页做一次手动备份（旧版备份可被 1.1.0 恢复；反向不行——新备份不能恢复到旧程序上）
- 客户端数据无需重新下载：版本未变（v20.0），SHA-256 校验口径一致
