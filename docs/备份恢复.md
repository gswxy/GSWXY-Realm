# 备份与恢复

> 备份的目标是：任何时候都能可靠地把服务器恢复到某个时间点。

## 备份包含什么

| 内容 | 说明 | 可否重新获取 |
| --- | --- | --- |
| `acore_auth`（账号库，完整） | 账号、SRP6 凭据、GM 等级、封禁记录 | ❌ 不可丢失 |
| `acore_characters`（角色库，完整） | 角色、进度、背包、公会、玩家机器人表 | ❌ 不可丢失 |
| `acore_playerbots`（机器人库，完整） | 机器人绑定、自定义策略、任务与装备缓存 | ❌ 不可丢失 |
| `acore_world`（世界库关键表） | 中文化与常见管理操作涉及的表（creature/item/quest/goossip/broadcast/acore_string 等） | ⚠️ 部分可从 FPK 重导，但你的修改会丢 |
| 用户配置 | `var/config`（三层模型的用户层） | ❌ 不可丢失 |
| 状态文件 | 初始化状态、Realm 名称等 | ⚠️ 建议随备份 |
| 版本信息 | manifest 记录产品版本、Core/Playerbots commit、数据版本 | 恢复校验用 |
| **客户端数据**（dbc/maps/...） | **不在备份内** | ✅ 官方源随时重下（约 1.1 GB） |

每份备份是单个 `gswxy-backup-<时间戳>.tar.gz`，内含逐成员 SHA-256 清单（`manifest.json`），恢复前逐一校验，损坏即拒绝。

## 创建备份

- 手动：「备份」页 → 立即备份
- 自动：勾选「每日自动备份」——超过 24 小时没有新备份时自动创建；保留最近 **30 份** 且总占用上限 **24 GB**，超出自动清理最旧档案

## 恢复流程（做了什么）

1. **校验**：解包到临时目录（拒绝路径穿越/符号链接/超大成员），核对 manifest 与每个成员的 SHA-256；备份若来自比当前安装更新的程序版本则直接拒绝
2. **自动快照**：先把当前状态再备份一份（随时可以"恢复的恢复"）
3. **静默游戏服务器**：停止 WorldServer / AuthServer（数据库保持运行——导入需要它）
4. **导入**：按 账号 → 角色 → 世界 → 机器人 顺序重放 SQL；任何一步失败即中止并报告，不会伪报成功
5. **合并状态**：Realm 名称、中文数据版本等跟随备份；数据库端口、客户端数据记录、初始化进度等**保留本机值**（跨机器恢复的关键：备份里的端口属于源机器）
6. **拉起服务**：恢复前在运行的服务自动重启

## 跨机器恢复

1. 目标 NAS 安装同版本（或更新版本）应用并完成初始化
2. 把备份文件放入目标机器的 `var/backups/` 目录
3. 在「备份」页执行恢复

## 限制与说明（如实）

- 备份包含数据库凭据哈希等敏感数据：档案权限 0600，**不要把备份包发给不可信的人**
- 恢复会整体回滚数据库到备份时间点：之后的账号、角色进度、机器人变化都会丢失（所以恢复前会自动再快照）
- 降级场景（旧程序 + 新备份）被拒绝；请先升级应用再恢复
- 客户端数据不备份：恢复后如提示缺目录，到「数据」页重新下载即可
